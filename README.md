# CMG Payroll

โครง Vite + React สำหรับระบบบริหารจัดการค่าแรง โดยจัดเมนูตามไฟล์ Excel ต้นแบบและเตรียม Firestore สำหรับจัดเก็บข้อมูล

## เริ่มต้นใช้งาน

```bash
npm install
copy .env.example .env
npm run dev
```

ถ้ายังไม่ใส่ค่า Firebase ระบบจะเปิดด้วยข้อมูลตัวอย่างและบันทึกเฉพาะในหน้าจอ เมื่อใส่ค่า `VITE_FIREBASE_*` ครบ ระบบจะใช้ anonymous authentication เพื่ออ่าน/เขียน Firestore และอัปโหลดไฟล์เข้า Storage อัตโนมัติ ค่าใน `.env` จะไม่ถูก commit เพราะอยู่ใน `.gitignore`

## Sync ทะเบียนพนักงานจาก Master Database

หน้า `อัตราค่าแรง` มีปุ่ม `Sync ข้อมูล` สำหรับอ่านข้อมูลจาก Firestore ของโปรเจกต์ Master Database ที่ collection:

```text
CMG-HR-Database/root/employee_data
```

ค่าการเชื่อมต่อของฐานข้อมูลต้นทางเก็บใน `.env` ด้วย prefix `VITE_MASTERDATABASE_*` ระบบจะแปลงฟิลด์ `รหัสพนักงาน`, `ชื่อตัว`, `ชื่อสกุล`, `ชื่อชุด` (แผนก), `ตำแหน่ง`, `สถานะโครงการ` (โครงการ) และ `สถานะพนักงาน` แล้ว upsert เข้า Firestore ที่ `CMG-Payroll/root/rates` โดยจับคู่ด้วยรหัสพนักงาน

- แท็บ `DC` รับรหัสขึ้นต้น `DC` และ `Intern` ส่วนแท็บ `SUPPLY` รับรหัสขึ้นต้น `SP` รหัสอื่นไม่นำเข้า
- นำเข้าเฉพาะสถานะพนักงาน `ทำงาน` ส่วนรายการที่เคยนำเข้าแล้วแต่เปลี่ยนเป็นสถานะอื่นจะถูกซ่อนจากตาราง
- คอลัมน์ `โครงการ` มาจากฟิลด์ `สถานะโครงการ` (หลายโครงการคั่นด้วย `, `) และบันทึกไว้ในแอปนี้
- การ Sync ครั้งถัดไปจะอัปเดตเฉพาะฟิลด์จากต้นทาง และรักษาฟิลด์อัตราค่าแรง/สวัสดิการที่กรอกไว้ในระบบเดิม

## เปิดให้เครื่องอื่นในวง LAN เข้าใช้งาน

Vite ถูกตั้งค่าให้ listen ทุก network interface แล้ว ให้ดู IPv4 ของเครื่องที่รัน dev แล้วเปิดจากเครื่องอื่นด้วยรูปแบบนี้:

```text
http://<IP-เครื่องที่รัน>:5173
```

ตัวอย่าง `http://192.168.1.25:5173` เครื่องทั้งสองต้องอยู่เครือข่ายเดียวกัน และถ้า Windows Firewall ถาม ให้เลือกอนุญาตเฉพาะเครือข่าย Private

## โครงสร้าง Firebase ที่ใช้งานจริง

ข้อมูลทุกผู้ใช้ รวมถึง anonymous user ใช้พื้นที่เดียวกัน โดยไม่มีโฟลเดอร์ตาม UID:

```text
CMG-Payroll (collection)
└── root (document)
    ├── rates (subcollection)
    │   └── {documentId}
    ├── payroll (subcollection)
    │   └── {documentId}
    └── payrollPeriods (subcollection)
        └── {periodId}
            └── revisions (subcollection)
                └── {revisionId}
                    └── rows (subcollection)
                        └── {rowId}
```

หน้า `ค่าแรงรายงวด` จะดึงรายชื่อที่มองเห็นได้จาก `rates` มาแสดงอัตโนมัติในทุกแท็บ โดยแท็บ `ซอ` ใช้ชุดรายชื่อจาก `SUPPLY` และตั้งค่าตัวเลขเริ่มต้นเป็น `0` ผู้ใช้สามารถเปิดงวดใหม่ได้จากมุมบนขวา

การกด `บันทึก` จะเปิด Modal ให้ตั้งชื่อ Revision แล้วบันทึก snapshot ของตารางทั้ง 3 แท็บเป็นเอกสารใหม่ใต้ `payrollPeriods/{periodId}/revisions/{revisionId}` พร้อมแถวข้อมูลใน `rows` ทุก Revision มีสถานะ `Savedraft` และ Revision เดิมจะไม่ถูกเขียนทับ

เอกสารใน `rates` และ `payroll` มี `sheet` เพื่อแยกแท็บ เช่น `DC`, `SUPPLY`, `ซอ` ส่วนไฟล์แนบจะอยู่ใน Storage path `CMG-Payroll/root/{category}/{sheet}/{documentId}/...` และ metadata จะถูกเก็บในฟิลด์ `attachments`

ต้องเปิด Anonymous sign-in ใน Firebase Authentication หาก Rules ของโปรเจกต์กำหนดให้ผู้ใช้ต้อง authenticated

รายละเอียดฟิลด์อยู่ที่ [docs/data-model.md](docs/data-model.md)

## โครงสร้างหน้าจอ

- ภาพรวม: ยอดรวมและทางลัดไปยังข้อมูลหลัก
- ค่าแรงรายงวด: แท็บ `DC`, `SUPPLY`, `ซอ` และแบ่งตารางหน้าละ 50 รายการ โดย render เฉพาะหน้าปัจจุบัน
- อัตราค่าแรง: แท็บ `DC`, `SUPPLY`

## Import / Export อัตราค่าแรง

ในเมนู `อัตราค่าแรง` มีปุ่มสำหรับ:

- `ดาวน์โหลด Template` สร้างไฟล์ Excel 11 คอลัมน์ตามต้นแบบ: `รหัสพนักงาน`, `ชื่อ`, `นามสกุล`, `แผนก`, `ตำแหน่ง`, `ค่าแรงปี69`, `อัตราค่าเดินทาง`, `ตำแหน่งพิเศษ`, `ค่าแรงตำแหน่งพิเศษ`, `ค่าโทรศัพท์`, `สวัสดิการช่วยเหลือ`
- `Export` ส่งออกข้อมูลของแท็บที่เปิดอยู่เป็น `.xlsx`
- `Import DC + SUPPLY` นำเข้าไฟล์เดียว (`.xlsx`, `.xls`, `.csv` หรือ `.tsv`) แล้วกระจายข้อมูลไปแท็บ `DC` และ `SUPPLY` ตาม `รหัสพนักงาน` ที่มีอยู่ในระบบ จากนั้นอัปเดตเฉพาะ `ค่าแรงปี 69`, `อัตราค่าเดินทาง`, `ตำแหน่งพิเศษ`, `ค่าแรงตำแหน่งพิเศษ`, `ค่าโทรศัพท์` และ `สวัสดิการช่วยเหลือ` พร้อมตั้ง `สถานะ` เป็น `ทำงาน`

หลังเลือกไฟล์ ระบบจะแสดง Modal สรุปก่อนบันทึก โดยแสดงรหัสที่อัปเดตได้ รหัสที่ไม่พบในระบบ รหัสที่มีค่าตัวเลขผิดรูปแบบ และรหัสซ้ำ ผู้ใช้ต้องกด `ยืนยัน Import` จึงจะบันทึกข้อมูล

คอลัมน์ `ตำแหน่งพิเศษ` ต้องตรงกับรายการที่สร้างไว้ในปุ่ม `จัดการตัวเลือก` หากไม่ตรง ระบบจะไม่ให้ยืนยัน Import และจะแจ้งให้สร้างรายการให้ตรงก่อน

ระบบรองรับหัวตารางภาษาไทย/อังกฤษและหัวตารางเดิม เช่น `นามสกุล`, `ชื่อสกุล`, `หมายเหตุ` และ `ชื่อชุด` รหัสที่มีเฉพาะในไฟล์แต่ไม่มีในระบบจะไม่ถูกสร้างเป็นรายการใหม่ และข้อมูลชื่อ/แผนก/ตำแหน่ง/โครงการจะไม่ถูกแก้ไขจาก Import

กติกาค่าเดินทาง: ถ้า `อัตราค่าเดินทาง` เป็น `พักแคมป์` หรือ `พักแค้มป์` ระบบจะคิดค่าเดินทางเป็น `0` และไม่นำไปรวมในยอดสุทธิ
